# 钓鱼乐园（Fishing Club）

一个面向钓友的移动端 Web 应用：浏览钓场与鱼种、在线预约、收藏、聊天室交流，配套一套完整的管理后台。

本仓库是原 **PHP + MySQL** 版本的重写版 —— 使用 **Node.js + Express + SQLite**，不依赖任何外部数据库服务，克隆下来即可直接运行。

## 快速开始

```bash
# 1. 安装依赖
npm install

# 2. 启动
npm start          # 默认 http://localhost:3000

# 指定端口
PORT=8080 npm start
```

首次启动会自动建库建表并写入演示数据（数据库文件位于 `data/fishing.db`）。

## 技术选型

| 关注点 | 方案 |
| --- | --- |
| Web 框架 | Express 4 |
| 数据库 | SQLite（优先 Node 内置 `node:sqlite`，无则回退 `better-sqlite3`） |
| 会话 | `express-session` + 自实现 SQLite Store |
| 密码 | `bcryptjs`（bcrypt，cost 10）；兼容历史 MD5 记录 |
| 上传 | `multer` 2.x（文件名重写、类型白名单） |
| 验证码 | 服务端生成内联 SVG，无需图像库 |
| 模板 | 原生模板字符串 + `esc()` 转义（等价 `htmlspecialchars`） |

### 为什么保留 `.php` 后缀？

原项目的页面文件名、站内链接、表单 action 全部指向 `*.php`。重写时**原样保留了这些路径**（如 `/index.php`、`/login.php`、`/admin_order.php`），因此所有页面内的相对链接、返回跳转、后台菜单都无需任何改动，迁移风险最小。这些路由由 Express 提供，与 PHP 无关。

## 安全说明

重写过程中修复了原 PHP 版本的多处缺陷，并补充了以下防护：

- **SQL 注入** —— 全部使用参数化查询，无字符串拼接。
- **XSS** —— 所有动态输出经 `esc()` 转义。
- **密码存储** —— 一律 bcrypt 加盐哈希（`$2y$`，cost 10）；登录时兼容校验历史 MD5 记录，便于旧库平滑迁移。
- **后台登录防爆破** —— 同一来源 IP 在 15 分钟内连续失败 5 次即锁定 15 分钟，锁定期内即使密码正确也拒绝；登录成功立即清零。计数落库（`login_attempt` 表），进程重启不会失效。
- **CSRF** —— 采用 Fetch Metadata（`Sec-Fetch-Site`，回退 `Origin` / `Referer`）做同源校验，拦截跨站状态变更请求。
- **会话安全** —— `HttpOnly` Cookie；会话密钥 `SESSION_SECRET` 不再硬编码，未设置时自动生成随机密钥并持久化到 `data/.session-secret`。
- **越权（IDOR）** —— 订单、收藏等资源均校验归属，个人中心只返回本人数据。
- **上传安全** —— 固定目录、重写文件名、校验图片类型与大小。
- **错误处理** —— 统一友好错误页，绝不回显数据库原始报错。
- **路径穿越** —— 静态目录与兜底路由均做了归一化处理。

### 原版缺陷修复记录

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| `users` 表缺 `signature` / `email` / `reg_time` | 个人中心相关功能报错 | 补齐字段 |
| `fishing_images.title` NOT NULL + UNIQUE | 后台上传轮播图必然失败 | 放开约束 |
| `user.php` 改密码用 MD5 校验 bcrypt 哈希 | 改密码永远失败 | 改为 bcrypt 校验 |
| `orders` 表缺 `book_id` / `money` | 确认预约生成订单失败 | 补齐字段 |
| `admin_book.php?confirm` 写入 `status=0` | 与订单状态枚举冲突 | 修正为 `status=1` |
| 数据库报错直接回显给用户 | 信息泄露 | 统一错误页 + 服务端日志 |
| `/uploads/xxx` 兜底用相对重定向 | 无限重定向循环 | 改为绝对路径 `/index.php` |
| 改资料无任何校验 | 可把用户名改成空 / 重名，账号永久不可用 | 补充必填、长度、唯一性校验 |
| 无 CSRF 防护 | 跨站可触发删除等操作 | 同源校验中间件 |
| 管理员密码用无盐 MD5 存储 | 弱口令的 MD5 可被秒级反查，等于明文 | 改为 bcrypt 加盐（密码不变），代码保留 MD5 兼容校验 |
| 后台登录无失败次数限制 | 可无限次暴力尝试密码 | 按来源 IP 计次并锁定（`login_attempt` 表） |
